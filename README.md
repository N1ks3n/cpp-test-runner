# C++ Test Runner

Расширение для VS Code / Code OSS, которое собирает C++ проект
и запускает тесты CTest одной кнопкой.

Разработано в рамках лабораторной работы.

## Возможности

- Поиск каталогов сборки CMake в открытом проекте.
- Выбор каталога, если найдено несколько сборок.
- Создание каталога `build`, если сборок ещё нет.
- Сборка проекта перед запуском тестов.
- Вывод подробностей неуспешных тестов в панель Output.
- Сообщение об успешном прохождении всех тестов.
- Сохранение полного вывода CMake и CTest в файлы логов.
- Настройка параллельности и тайм-аута тестов.
- Сохранение истории запусков с ограничением её размера.
- Визуализация результатов и длительности запусков.

## Требования

- VS Code или Code OSS версии 1.96.0 или новее.
- CMake и CTest версии 3.21 или новее.
- C++ компилятор и инструменты сборки, необходимые проекту.

Команды `cmake` и `ctest` должны быть доступны через `PATH`.

Тесты проекта должны быть зарегистрированы в CTest.
Например:

```cmake
enable_testing()

add_executable(example_tests tests.cpp)

add_test(
    NAME example_test
    COMMAND example_tests
)
```

## Запуск расширения из исходников

Для разработки дополнительно необходимы Node.js и npm.

1. Склонируйте репозиторий и откройте его в VS Code.
2. Установите зависимости:

   ```bash
   npm ci
   ```

3. Соберите расширение:

   ```bash
   npm run build
   ```

4. Нажмите `F5`, выбрав конфигурацию `Run Extension`.

Откроется окно Extension Development Host.
Текущая конфигурация отладки открывает пример
из `examples/simple-tests`.

После изменения TypeScript-кода необходимо повторить сборку
и перезапустить отладку.

## Использование

Откройте папку C++ проекта и нажмите кнопку
**C++ Tests** в нижней строке редактора.

Расширение:

1. Найдёт существующие сборки по файлам `CMakeCache.txt`.
2. Предложит выбор, если сборок несколько.
3. Если сборок нет, настроит проект командой
   `cmake -S <проект> -B <проект>/build`.
4. Соберёт выбранную сборку.
5. Запустит тесты через CTest.
6. Покажет результат и сохранит статистику.

При ошибке настройки или компиляции тесты не запускаются.

Результаты отображаются в панели **Output**:
**View → Output** или `Ctrl+Shift+U`,
канал **C++ Test Runner**.

Полный вывод CTest также доступен в канале
**C++ Test Runner Diagnostics**.

Тест, завершившийся по тайм-ауту, считается неуспешным.

## Команды

Команды доступны через палитру `Ctrl+Shift+P`.

| Команда | Назначение |
| --- | --- |
| C++ Test Runner: Run Tests | Собрать проект и запустить тесты |
| C++ Test Runner: Open Settings | Открыть настройки расширения |
| C++ Test Runner: Show Statistics | Открыть статистику запусков |

## Настройки

Откройте настройки через `Ctrl+,` и найдите `cppTestRunner`.

Параметры можно задавать для пользователя или отдельного проекта.

| Параметр | Назначение |
| --- | --- |
| `cppTestRunner.logs.enabled` | Сохранять логи в файлы |
| `cppTestRunner.logs.directory` | Папка сохранения логов |
| `cppTestRunner.tests.parallelJobs` | Максимальное число одновременно выполняемых тестов |
| `cppTestRunner.tests.timeoutSeconds` | Тайм-аут одного теста в секундах |
| `cppTestRunner.statistics.historyLimit` | Максимальное число сохранённых запусков, от 1 до 1000 |

Пример настроек проекта в `.vscode/settings.json`:

```json
{
  "cppTestRunner.logs.enabled": true,
  "cppTestRunner.logs.directory": "test-logs",
  "cppTestRunner.tests.parallelJobs": 2,
  "cppTestRunner.tests.timeoutSeconds": 60,
  "cppTestRunner.statistics.historyLimit": 100
}
```

Параллельность относится к выполнению тестов, а не к компиляции.
Заданный проектом CMake параметр `TIMEOUT` конкретного теста
имеет приоритет над общим тайм-аутом.

## Логи

При включённом логировании для каждого запуска сохраняется
отдельный файл с выводом настройки CMake, сборки и CTest.

Относительный путь папки логов считается от открытой папки проекта.
Можно указать абсолютный путь. Сокращение `~` не раскрывается.

Файл записывается после завершения запуска.
При аварийном закрытии редактора незаписанный лог может потеряться.

## Статистика

Откройте **C++ Test Runner: Show Statistics**.

Панель содержит:

- количество сохранённых запусков;
- суммарное число успешных и неуспешных выполнений тестов;
- диаграмму результатов по запускам;
- диаграмму длительности запусков;
- таблицу истории с датой, результатами, длительностью,
  кодом завершения CTest и каталогом сборки.

Диаграммы показывают до 30 последних запусков.
Таблица содержит всю сохранённую историю в пределах заданного лимита.

Длительность измеряется для выполнения CTest,
без настройки CMake и компиляции.

История хранится средствами VS Code отдельно от текстовых логов
и сохраняется между перезапусками редактора.
Выключение логирования не отключает статистику.

При превышении лимита удаляются самые старые записи.
Уменьшение лимита применяется при следующем запуске тестов
или открытии статистики.

Ошибки сборки и запуски без читаемого XML-отчёта
в статистику результатов тестов не добавляются.

## Демонстрационный проект

В `examples/simple-tests` находится CMake-проект с двумя тестами:

- `addition_passes` — успешный тест;
- `subtraction_fails` — намеренно неуспешный тест.

Ручной запуск из корня репозитория:

```bash
cmake -S examples/simple-tests -B examples/simple-tests/build
cmake --build examples/simple-tests/build
ctest --test-dir examples/simple-tests/build --output-on-failure
```

Падение второго теста ожидаемо: он демонстрирует обработку ошибок.

## Ограничения

- Используется первая открытая папка рабочего пространства.
- Поиск сборок выполняется только внутри этой папки.
- Если сборок нет, `CMakeLists.txt` должен находиться в её корне.
- Автоматический выбор исходного проекта среди нескольких
  независимых CMake-проектов не реализован.
- CMake Presets и выбор конфигурации многоконфигурационных
  генераторов пока не поддерживаются.
- Расширение запускает тесты, зарегистрированные в CTest,
  а не ищет тестовые функции в C++ исходниках.
